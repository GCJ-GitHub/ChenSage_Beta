# ChenSage AgentOS Beta1.0 功能开发顺序

> 版本：Beta1.0  
> 修订日期：2026-07-09  
> 目标：按 MVP 已验证功能逐步迁移到 AgentOS 架构，先跑通任务主链路，再恢复并增强具体产品功能。

---

## 1. 排序原则

Beta1.0 的开发顺序遵循四个原则：

- 先主链路，后复杂能力：先让任务能创建、入队、执行、更新状态、查看结果。
- 先低外部依赖，后高外部依赖：先做内容创作和模型设置，再做网页、RSS、arXiv、批量抓取。
- 先统一底座，后功能扩展：任务中心、模型设置、提示词模板、文件管理是多个功能共用底座。
- 每个功能都进入 task-svc：不要绕过统一任务中心做孤立页面。

---

## 2. 总体顺序

推荐顺序：

```text
0. 基础项目骨架和本地依赖
1. 任务中心与任务执行主链路
2. 模型设置
3. 提示词模板
4. 内容创作与改写
5. 历史任务与 Markdown 导出
6. 文件管理与解析
7. 模拟面试
8. 信息搜集
9. arXiv 日报
10. 活记忆、评估和观测增强
```

---

## 3. 阶段 0：基础项目骨架和本地依赖

### 目标

让项目具备可持续开发的基本形态。

### 开发内容

- 前端目录：`apps/web`。
- 后端服务目录：`services/gateway`、`services/task-svc`、`services/model-svc`、`services/agent-svc`。
- Worker 目录：`workers/agent-worker`。
- 共享契约目录：`packages/shared`。
- 本地基础设施目录：`infra/docker`。
- Docker Compose 准备 PostgreSQL、RabbitMQ、Redis、MinIO。

### 完成标准

- 本地可以启动基础依赖。
- 前端、后端、worker 目录边界清晰。
- `.env.example`、README、基础配置结构齐全。

---

## 4. 阶段 1：任务中心与任务执行主链路

### 为什么先做

任务中心是所有功能的共同入口。内容创作、面试、信息搜集、arXiv 日报、文件解析和导出都应该是 task，而不是各自维护一套状态。

### 开发内容

- `task-svc`：
  - task 创建。
  - task 状态机：`queued`、`running`、`succeeded`、`failed`、`cancelled`。
  - task event。
  - task result。
  - retry 和 cancel 的接口预留。
- RabbitMQ：
  - task 队列。
  - worker 消费。
- `agent-worker`：
  - 消费任务。
  - 执行一个最小 stub 任务。
  - 写回状态和结果。
- `apps/web`：
  - 任务创建页。
  - 任务列表页。
  - 任务详情页。

### 完成标准

- 用户能在前端创建一个任务。
- 任务进入队列后被 worker 消费。
- 前端能看到任务状态从 `queued` 到 `running` 再到 `succeeded` 或 `failed`。
- 任务详情页能展示事件和最终结果。

---

## 5. 阶段 2：模型设置

### 为什么第二个做

内容创作、面试、信息搜集摘要和日报生成都依赖模型。先把模型配置统一起来，后续 Agent 不直接处理 API Key。

### 开发内容

- `model-svc`：
  - OpenAI-compatible API base URL。
  - API Key 保存和脱敏展示。
  - 默认模型配置。
  - 连通性测试。
  - 简单 chat completion 调用。
- `apps/web`：
  - 模型设置页。
  - 连通性测试按钮。
  - 默认模型选择。

### 完成标准

- 用户可以配置 OpenAI-compatible Provider。
- 可以测试连通性。
- `agent-worker` 或 `agent-svc` 可以通过 `model-svc` 完成一次最小模型调用。
- 日志不输出完整 API Key。

---

## 6. 阶段 3：提示词模板

### 为什么第三个做

原 MVP 的内容创作、信息搜集、arXiv 日报都依赖模板。模板先统一，后续功能就不是散落的硬编码 Prompt。

### 开发内容

- `agent-svc` 内 prompt registry：
  - 模板列表。
  - 模板详情。
  - 按任务类型分类。
  - 模板变量 schema。
  - 模板版本字段预留。
- `apps/web`：
  - 模板列表页。
  - 模板编辑页。
  - 模板变量预览。

### 完成标准

- 可以为不同任务类型维护模板。
- 内容创作任务可以选择模板。
- 模板变量可以被 task input 填充。

---

## 7. 阶段 4：内容创作与改写

### 为什么优先恢复这个产品功能

内容创作链路短、外部依赖少，最适合作为第一个真实 Agent 功能。它能验证任务、模板、模型、导出和评估的主要边界。

### 开发内容

- `content-agent`：
  - 内容生成。
  - 内容改写。
  - 风格、平台、长度、语气参数。
  - 支持论文、专利、小说、剧本、歌词、小红书、知乎、公众号等类型。
- `task-svc`：
  - task_type：`content_generation`、`content_rewrite`。
- `apps/web`：
  - 内容创作页。
  - 内容类型选择。
  - 模板选择。
  - 结果预览。

### 完成标准

- 用户能创建内容创作任务。
- 任务通过模板和模型生成结果。
- 结果进入统一历史任务。
- 支持至少 Markdown 形式的结果展示。

---

## 8. 阶段 5：历史任务与 Markdown 导出

### 为什么此时做

内容创作完成后，马上补历史任务和导出，可以让第一条真实产品链路闭环。

### 开发内容

- `task-svc`：
  - 历史任务筛选。
  - 任务重试。
  - 任务结果查询。
- `tool-registry` 或导出模块：
  - Markdown export。
- `file-svc`：
  - 导出产物元数据。
  - MinIO object key。
- `apps/web`：
  - 历史任务页。
  - 重试按钮。
  - 导出 Markdown 按钮。

### 完成标准

- 所有内容创作任务可在历史任务中查看。
- 失败任务可重试。
- 成功任务可导出 Markdown。

---

## 9. 阶段 6：文件管理与解析

### 为什么放在面试前

模拟面试依赖简历文件，信息搜集也依赖 PDF / TXT / MD 解析。先做文件底座，可以复用到多个功能。

### 开发内容

- `file-svc`：
  - 文件上传。
  - 文件元数据。
  - MinIO 存储。
  - 解析状态。
- `tool-registry`：
  - PDF parse。
  - DOCX parse。
  - TXT / MD parse。
- `apps/web`：
  - 文件列表页。
  - 上传入口。
  - 解析结果预览。

### 完成标准

- 用户能上传 PDF、DOCX、TXT、MD。
- 文件能被解析为文本。
- 解析结果可以被后续任务引用。

---

## 10. 阶段 7：模拟面试

### 开发内容

- `interview-agent`：
  - 简历分析。
  - 岗位描述分析。
  - 面试问题生成。
  - 回答评价。
  - 复盘报告。
- `eval-svc`：
  - 回答完整性、匹配度、表达质量评估。
- `apps/web`：
  - 简历选择 / 上传。
  - JD 输入。
  - 问题列表。
  - 回答输入。
  - 复盘报告页。

### 完成标准

- 用户可以基于简历和 JD 创建模拟面试任务。
- 系统能生成问题。
- 用户回答后能得到评价和复盘报告。
- 面试结果进入历史任务。

---

## 11. 阶段 8：信息搜集

### 为什么后置

信息搜集涉及网页访问、RSS、JSON、PDF、批量任务和站内发现，外部不确定性更高。等任务、文件、模板、模型稳定后再做更稳。

### 开发内容

- `research-agent`：
  - 单 URL 摘要。
  - PDF 信息提取。
  - JSON 数据提取。
  - RSS 拉取和摘要。
  - 批量多任务。
  - 站内信息发现。
  - 汇总报告。
- `tool-registry`：
  - web fetch。
  - RSS parse。
  - JSON parse。
  - site discovery。
- `policy-svc`：
  - 外部域名白名单。
  - SSRF 防护。
- `apps/web`：
  - 信息搜集任务创建页。
  - 批量任务进度页。
  - 汇总报告页。

### 完成标准

- 支持单 URL / PDF / JSON / RSS 信息搜集。
- 支持批量任务。
- 支持生成 Markdown 汇总报告。
- 外部请求经过 policy-svc 规则。

---

## 12. 阶段 9：arXiv 日报

### 开发内容

- `research-agent` 的 arXiv workflow：
  - 研究方向管理。
  - 关键词配置。
  - arXiv category 配置。
  - 按日期和篇数拉取论文。
  - 论文摘要和筛选。
  - 收藏论文。
  - 按日期范围生成日报。
- `apps/web`：
  - 研究方向页。
  - arXiv 拉取任务页。
  - 收藏列表。
  - 日报生成页。

### 完成标准

- 用户可以配置研究方向。
- 可以按日期和篇数拉取论文。
- 可以收藏论文。
- 可以按范围生成 Markdown 日报。

---

## 13. 阶段 10：活记忆、评估和观测增强

### 开发内容

- `living-memory-svc`：
  - 任务偏好沉淀。
  - 用户确认长期记忆。
  - 冲突检测。
  - 过期降权。
- `eval-svc`：
  - 内容质量评估。
  - 引用完整性评估。
  - 事实风险提示。
- 可观测：
  - task trace。
  - loop step trace。
  - tool call trace。
  - token / cost。
  - eval report。

### 完成标准

- 用户可以查看、确认、冻结、删除记忆。
- 复杂任务生成 eval report。
- 任务详情页能展示关键 trace 和成本信息。

---

## 14. 第一条建议实现链路

最推荐从这条链路开始：

```text
模型设置
  -> 提示词模板
  -> 内容创作任务
  -> worker 执行
  -> model-svc 调用模型
  -> task-svc 写回结果
  -> 历史任务查看
  -> Markdown 导出
```

它覆盖了 Beta1.0 的核心底座，又能最快恢复一个真实 MVP 功能。
